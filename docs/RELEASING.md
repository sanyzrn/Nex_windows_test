# Windows CI and releases

Current application: **0.20.0+13**, release tag **v0.20.0**. `main` contains
one current source tree at the repository root. Build caches and installer
EXEs are excluded from Git; installers belong in Releases.

## Reviewed visual baselines

The 0.20.0 workspace adds a tag-colored gallery and Android-compatible cloud intelligence, retaining all 14 shared palettes.
Windows baselines were generated by Windows CI with Flutter 3.44.8, reviewed and
committed. The full desktop suite then passed in comparison mode. CI compares
these images; it must not regenerate expected images before testing. Only
explicitly listed emoji-grid screenshots permit up to 0.05% Windows emoji-font
drift; dimensions and other screenshots remain exact.

## Build and publish

1. Update version declarations, changelog and current documentation.
2. Run analysis, affected checks and desktop/shared-package tests.
3. Commit and push main. Desktop Windows CI tests the source and builds setup.
4. On successful completion, **Publish tested Windows release** runs
   automatically, checks the exact CI commit and installer checksum, creates
   `v<version>` and publishes setup plus `SHA256SUMS` as the latest release.

No manual build, tag or release dispatch is needed. For each subsequent update,
increase the app's source version and changelog together; the existing version
consistency tests check all version declarations. A published version is not
replaced by later commits with the same number. Re-running its successful CI is
safe: the publisher skips an already complete release. An existing version tag
can still be supplied to manual dispatch for a retry.

CI uses pinned actions, Flutter 3.44.8 and SHA-verified Inno Setup 6.7.3.
It checks package hosts, versions and UI hygiene, runs desktop/shared UI
suites, builds and packages Windows, and checks on-device runtime removal. Seventeen
isolated PowerShell checks exercise publication without network or real writes.
The publisher accepts only successful main/master push runs from this repository,
skips superseded commits, checks the matching artifact and prevents downgrades.
PR runs, failed CI, incomplete assets and mismatched tags/checksums cannot publish.

## Current artifact and synchronization

Use the installer and checksum attached to the same GitHub release. A checksum
from an older source checkout does not describe a new installer. Compiler and
environment differences can change binary hashes; publication uses the tested
CI artifact directly rather than rebuilding it in the publishing workflow.

Fetch before comparing HEAD with origin/main. Tracked changes must be absent
and ahead/behind counts must be 0 0. Historical commits and changelog entries
are retained. Obsolete installer copies, release assets and version tags are
removed only after the current release is verified.
