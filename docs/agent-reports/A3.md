Base: `ca75581`, branch `windows/0.23-agent`. Owner approved Part 3.

1. Recover the exact published branch after the execution environment was replaced.

3. Render capture, library, reader, assistant, tools and settings at all four requested sizes.

8. Commit/push the completed part; stop before A4 for owner approval.

## Changes and reasons

- The compact rail scrolls its upper destinations independently of the footer.
  The compact destination uses the existing Assistant/دستیار label so its name
  fits at normal text size and leaves more room for the page title at 200%.
  At larger text sizes its width is measured from complete localized labels;
  the wide rail also reserves enough room for complete words. No label is scaled
  back down to fit. The 76px compact rail remains unchanged at text scale 1.0.
- Capture actions wrap naturally and use fewer columns as scaled space shrinks.
  The checklist label can wrap beside its switch. Reader actions use one/two
  columns where necessary; their requested font size is preserved.
- Section titles wrap and move above header actions when needed. The assistant
  title and reader type badge are bounded; the duplicate assistant heading yields
  space in a short window that already has a section title; a narrow reader moves its badge below
  the back/pin/edit controls rather than clipping the type name.
- Library search gets its own row when space is limited. Its hint can wrap, the
  decorative Ctrl+F badge yields its space, and all three header controls remain.
  First-run/filtered-empty library content and the empty reader can scroll.
- The settings intro stacks its decorative icon above the text when scaled space
  is too narrow. Existing navigation, data operations, shortcuts and focus rings
  are retained.
- `NexWorkspaceDestination` permits wrapping instead of truncating the wide-rail
  label. This is the only shared-package source change; Android is untouched.
- The review fixture moved unchanged into `test/support/review_fixture.dart` so
  ordinary Linux layout tests and Windows snapshots exercise the same real shell,
  seeded SQLite notes and mocked native/AI services. All 54 existing review names
  and their order are retained. No tolerance or baseline was deleted/relaxed.

## Regression evidence

At base `ca75581`, the initial 288-case populated-screen sweep had **272 passes and
16 failures**: narrow reader headers, the assistant title, and the Persian rail at
200% text. The added 48 empty-library cases had **36 passes and 12 failures** (all
380×520 empty-library combinations). The original six full-size/reachability
control cases also failed before the fixes. These are reproduced defects, not
inferences from source alone.

The final sweep has **336 cases**: capture, populated library, empty library,
reader, assistant, tools and settings × 380×520 / 460×760 / 700×900 / 1200×800 ×
1.0 / 1.5 / 2.0 text × EN/FA × light/dark. Ten additional tests check complete
words, no truncation or geometric font shrinking, navigation/action reachability,
reader labels, library hints and first-run actions. Pixel references add **52
cases**, including every initially failing layout case and representative scaled
capture/reader controls. Preview-note ellipses remain intentional content previews;
text input still scrolls horizontally while typing.
