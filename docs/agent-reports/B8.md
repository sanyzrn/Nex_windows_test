# B8 — optional desktop modules

Owner selection (2026-10-21): PDF reader, private area, writing portrait and cycle.
Windows-only extras are outside this bundle. Base: published 0.23.0, main fcdea02.
Branch: `windows/b8-modules`. Version remains 0.23.0+17; changes are Unreleased.

## Delivered behavior

- Independent, device-only switches in Settings → Tools, off by default. Enabled
  modules also appear in the window's Tools directory; panel users can open each
  from its settings row. Turning a module off preserves its data.
- Offline PDFium reader for selected PDFs and PDF note attachments: horizontal
  reading in the interface direction, previous/next, zoom, encrypted-document
  password prompt, text search with highlighted matches, direct numbered page
  selection. Scanned pages require OCR; no OCR is claimed. PDF links can open
  internal destinations or credential-free HTTP(S), never executable/custom schemes.
- Passwords, bank cards and private text in Windows secure storage, outside the
  note database, search, AI and library backups. Android's validated v1 vault
  entry shape, serialized/read-back-verified writes, secure recoverable draft,
  card/IBAN checks and password generator are reused. Graceful Quit drains
  accepted secure writes before closing the platform engine. A read failure never
  replaces data with an empty vault. Finish an existing draft before replacing it.
- One process-only Windows Hello unlock shared by the vault and Cycle. Activity
  extends it; two idle minutes expire it. Blur removes private content and nested
  dialogs immediately. Cancelled/unavailable verification fails closed. Private
  copying excludes Nex/Windows clipboard history and cloud clipboard, clears its
  owned sequence after 30 seconds or at shutdown, and never clears a replacement.
- Local writing statistics reuse `nexWritingStats`. The optional AI portrait
  requires 30 notes over 7 days, configured AI/read consent and an explicit
  disclosure before each request. At most 80 short note excerpts are sampled;
  vault/cycle data are excluded. The previous portrait survives failed requests.
- Cycle uses the existing Android repository/predictor: period start/end,
  editable history, selected Persian/Gregorian calendar, typical lengths,
  mood/flow/symptoms/daily note and estimated next-period range. Daily changes
  queue immediately. Existing advanced Android day fields survive editing.
  The UI labels estimates as calendar estimates rather than clinical findings.

Design: tools stay quiet until selected, and the private tools share one calm
lock surface instead of repeated prompts. Existing Nex tokens, calendars,
editor direction handling and Android engines keep these modules in the same family.

## Verification and fixes

- Dart 3.12.2 analysis: no issues. Localization parity and diff hygiene passed.
  Lockfiles were resolved by Pub, not edited by hand; official Flutter 3.44.8
  source generators produced localizations and Windows plugin registration.
- PDF codec regression: image 4.11 requires `archive.decodeLazy`; the older
  locked archive 4.3 could not compile it. Require archive 4.5.2; a direct PNG
  encode/decode check passed. No schema or archive-format changes were made.
- [Windows review generation](https://github.com/sanyzrn/Nex_windows_test/actions/runs/39629505459) passed 226 cases, including 32 module surfaces,
  EN/FA, light/dark, compact/wide, and minimum-window 2x-text layout checks.
  All 32 new images and 12 affected Tools/release-history images were reviewed.
  It caught the empty PDF searcher's premature construction and a 2x cycle-ring
  overflow; both were fixed. Screenshot fixtures use the real filled surface.
- Focused regressions cover independent switches, the shared unlock and stale
  authentication, lock/blur removal of nested private dialogs, private copying,
  serialized vault/draft writes and corruption, cycle isolation/Android fields,
  PDF page selection and real PDF page turning/search/reopening, and mocked AI
  portrait consent. No real cloud API is called by tests.
- The existing Windows Release probe now renders/searches a synthetic two-page
  PDF in the actual EXE, round-trips a synthetic secure-storage value, and checks
  clipboard exclusion/cleanup. Full desktop/shared-package comparison, native
  build/probes and installer results are recorded in this bundle's PR checks
  and PR description; visual refresh alone is not a Release-build claim.
- All 16 notices from the pinned bundled PDFium distribution are retained and
  registered in About → Licenses. Native PDFium is a build asset; opening a local
  PDF does not download a runtime.

## Owner's physical checks

1. Windows Hello/PIN verification, denial/cancel/unconfigured devices; switch
   between private tools, alt-tab, Windows lock/sleep and wait beyond two minutes.
2. Copy a synthetic secret: check Nex history/Win+V, paste into a test field,
   wait 30 seconds, and confirm a later copied item is never erased.
3. Encrypted, large and Persian PDFs: wrong/cancelled password, text search,
   page navigation/zoom and reopening. Check real keyboard/Narrator/DPI behavior.
4. Android backup round-trips with cycle records; vault remains device-only.

These physical results are owned by the user and are not claimed complete.
