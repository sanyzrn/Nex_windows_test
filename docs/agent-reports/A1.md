## Changes and reasons

- Added `tools/check_l10n_parity.py` and 16 negative/positive regression tests.
  It rejects missing/empty/duplicate messages, mismatched placeholder names,
  types/formats, orphan metadata, bidi controls, malformed bilingual pairs and
  stale generated utility maps. It also catches direct multiline/lowercase and
  double-quoted UI literals missed by the PowerShell line regex. This focused
  source guard is not a full Dart AST or a runtime language detector.
- The existing desktop hygiene step runs that check and its tests before the
  original PowerShell check. No other workflow logic was changed.
- All 452 EN/FA ARB messages now share their message/placeholder contracts.
  Completed previously implicit metadata while retaining existing generated
  argument types/order, including `utility108(chars, lines, words)`.
- Moved commitment screen/editor text, cadence messages and weekday names to
  ARB. Weekday numeric IDs and Saturday-first Persian ordering are unchanged.
- Localized native backup/image picker filter labels and centralized the HEX
  hint. Added missing Left/Right utility translations used by panel-move toasts.
- Unified برچسب، سنجاق، جست‌وجو، پنل کناری، نسخهٔ پشتیبان and ارائه‌دهنده;
  normalized the existing friendly tone. Added `docs/glossary-fa.md`.
- Centralized language-neutral key names in `ShortcutLabels`. Shortcut help
  keeps key combinations LTR without storing bidi controls. Its new FA test
  exposed a 29-pixel row overflow: action labels and the title now wrap within
  the available width. Shortcut bindings themselves are unchanged.
- Added five Flutter tests for weekdays, cadence counts in both languages,
  and shortcut help direction/overflow. No shared package source, database,
  backup format, app version, main branch or release was changed.

## Risks and open verification

- Translation changes intentionally change Persian screenshot pixels. The existing
  Windows baseline-refresh workflow generated them on Windows; changed images were
  reviewed. This proves the visual suites run successfully in refresh mode, not
  that the full Windows build/native smoke/comparison workflow has run. That full
  workflow runs when the draft PR is opened at the end of Track A.
- Visual review caught the remaining old edge-panel naming and a few formal dock
  prompts. Those were corrected in `9cd6bdb`, with matching local after-images and
  a second successful Windows baseline refresh (`13d34a1`).
- Real Windows app launch, native file dialogs, DPI 100/125/150/200%, native smoke,
  Narrator and installer are not verified here. No claim that these passed.
- The full minimum-size/text-scale sweep belongs to A3, not this localization pass.
  English key names, API identifiers, brand/model names and technical input formats
  intentionally remain language-neutral. The glossary documents the exceptions.
- A2 remains unstarted. Owner approval is required before Part 2, as requested.
